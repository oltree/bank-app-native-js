# Bank App - SPA на нативном JavaScript

> **[Read in English](README.md)**

Полноценное одностраничное банковское приложение, написанное **исключительно на ванильном JavaScript** - без React, Vue и Angular. Каждый архитектурный элемент (роутер, управление состоянием, система компонентов, DOM-библиотека, HTTP-клиент) реализован с нуля, что демонстрирует глубокое понимание фундаментальных веб-технологий.

## Обзор

Проект создан как доказательство того, что SPA production-качества не требует фреймворка. Каждый паттерн, который принято считать «фичей фреймворка» - реактивное состояние, жизненный цикл компонентов, клиентский роутинг, scoped-стили - здесь реализован на чистом JavaScript.

Приложение имитирует реальный банковский интерфейс: пользователи могут авторизоваться, просмотреть карту и баланс, пополнять/снимать средства, переводить деньги другим пользователям, изучать историю транзакций и видеть аналитику доходов/расходов в виде самодельной диаграммы.

## Функциональность

### Аутентификация
- Регистрация и вход по email + паролю
- JWT Bearer-токен аутентификация
- Сохранение сессии в `localStorage` - переживает перезагрузку страницы
- Полный выход с очисткой состояния

### Управление картой и балансом
- Отображение номера карты в формате `xxxx xxxx xxxx xxxx`
- Копирование номера карты в буфер обмена одним кликом с визуальной обратной связью
- Переключение видимости CVC (скрыт по умолчанию)
- Баланс в реальном времени с форматированием через `Intl.NumberFormat` в рублях

### Транзакции
- Пополнение баланса
- Снятие средств
- Перевод другому пользователю по номеру карты
- После каждой операции: баланс, история и статистика обновляются автоматически через пользовательские DOM-события

### Контакты и переводы
- Поиск по списку контактов с аватарами
- Клик по контакту - номер карты автоматически подставляется в форму перевода
- Ввод суммы через prompt с валидацией

### История транзакций
- Полный список операций, отсортированный по убыванию даты
- Визуальное разграничение: доходы (зелёный) и расходы (красный)
- Удобочитаемый формат даты

### Статистика
- Диаграмма-пончик (реализована через чистый CSS + JS, без canvas/SVG-библиотек)
- Процентное соотношение доходов и расходов в реальном времени
- Обновляется после каждой транзакции

### UX-детали
- Система toast-уведомлений (успех / ошибка, автоскрытие)
- Валидация форм с инлайн-отображением ошибок
- Спиннеры загрузки во время асинхронных операций
- Анимация появления динамически вставляемого контента
- Страница 404 для неизвестных маршрутов

## Архитектура

### Клиентский роутер
Кастомный роутер на базе History API (`window.history.pushState`). Единственный обработчик клика на `document` перехватывает все переходы по ссылкам; маршруты описаны как пара путь → компонент в `routes.data.js`. Неизвестные пути автоматически отдают компонент 404.

### Реактивное состояние (паттерн Observer)
**Singleton Store** (`Store.getInstance()`) хранит всё состояние приложения. JavaScript `Proxy` перехватывает каждую операцию `set` и оповещает всех зарегистрированных наблюдателей. Без Redux, без MobX - только чистый паттерн Observer.

Состояние синхронизировано в обе стороны с `localStorage`, поэтому сессия и данные карты сохраняются между сессиями браузера.

### Система компонентов
Два базовых класса управляют UI:
- `ScreenComponent` - страничные компоненты (управляет `document.title`, рендерит в `#app`)
- `ChildComponent` - переиспользуемые под-компоненты (информация о карте, список транзакций, диаграмма и т.д.)

HTML-шаблоны хранятся как `.html`-файлы и парсятся `RenderService` через `DOMParser`. Кастомные теги `<component-*>` разрешаются и заменяются живыми экземплярами компонентов.

### Поток данных
```
Действие пользователя
  → Обработчик события в компоненте
  → API-сервис (обёртка JSQuery над fetch)
  → Колбэк onSuccess
  → Store.update()
  → Все наблюдатели оповещены → DOM перерисовывается
  → Toast-уведомление
```

## Собственный фреймворк

Директория `/core` содержит полноценный мини-фреймворк, написанный с нуля:

| Модуль | Описание |
|---|---|
| `core/router/` | Клиентский роутер на History API с fallback |
| `core/rquery/` | jQuery-подобная DOM-библиотека (чейнинг, события, CSS, хелперы для инпутов) |
| `core/js-query/` | HTTP-клиент на `fetch` с автоподстановкой Bearer-токена |
| `core/component/` | Базовые классы для страничных и дочерних компонентов |
| `core/services/render.service.js` | Парсер HTML-шаблонов и резолвер компонентов |
| `core/services/form.service.js` | Извлечение значений из форм |
| `core/services/storage.service.js` | Обёртка над localStorage с JSON-сериализацией |
| `core/services/validation.service.js` | Валидация полей с отображением ошибок |
| `core/services/notification.service.js` | Очередь toast-уведомлений |

**RQuery** (DOM-библиотека) поддерживает: `find`, `findAll`, `append`, `html`, `text`, `addClass`, `removeClass`, `css`, `show`, `hide`, `click`, `submit`, `on`, `value`, `attribute`, `numberInput`, `creditCardInput` - всё с чейнингом.

## Запуск

```bash
# Установка dev-зависимостей
npm install

# Запуск dev-сервера (http://localhost:5000)

npm run build
```

## API-интеграция

Все запросы к API проходят через кастомный HTTP-клиент `JSQuery`. Токен подставляется автоматически из `localStorage` при наличии.

| Метод | Эндпоинт | Описание |
|---|---|---|
| POST | `/api/auth/register` | Создание аккаунта |
| POST | `/api/auth/login` | Вход, получение токена |
| GET | `/api/users?searchTerm=` | Поиск пользователей |
| GET | `/api/cards/by-user` | Получение данных карты |
| PATCH | `/api/cards/balance/top-up` | Пополнение |
| PATCH | `/api/cards/balance/withdrawal` | Снятие |
| PATCH | `/api/cards/transfer-money` | Перевод на другую карту |
| GET | `/api/transactions?orderBy=desc` | История транзакций |
| GET | `/api/statistics` | Статистика доходов/расходов |
